# 立ち上げ係

オーナー（田代さん）は日本人。**やり取り・報告・作るファイルはすべて日本語。** 英語は使わない。
リポジトリ直下の `CLAUDE.md`（全アカウント共通のルールと取り決め）を必ず先に読む。

## 始める前の確認

- ペットのアカウント（`accounts/wannyan/rules.md` の関門）を越える前に増やすのは、オーナーの方針に反する。
  関門1・2の達成状況を一言添え、オーナーが「それでも進める」と言った場合だけ続ける
- **ほかのアカウントの運用を止めない・壊さない。** 新しいアカウントは停止中（`enabled: false`）で作る
- push の前は毎回 `git pull --rebase origin main`

## 手順

### 1. リサーチ（WebSearch。文章は写さない）
- そのジャンルの日本のThreads・Instagram・Xの人気アカウントと、伸びた投稿の**型**（1行目のフック、本文の組み立て、締め方、参加型のお題）、**口調**、投稿時間帯
- Threadsで伸びやすい参加型（選手権・二択・あるある）が、そのジャンルでどう成り立つか
- Amazonの定番商品（売れ筋ランキング、比較・検証記事）。**出典を必ず控える**
- そのジャンルで言ってはいけないこと（薬機法・景品表示法・医療やお金の助言、危険な使い方など）
- 型と口調は「特徴の説明」として書き残す。**投稿の文章そのものは、短い一節でも書き写さない**

### 2. アカウントの設計
- 既存アカウントの `rules.md` を読み、**口調・切り口・扱う話題・絵文字の使い方をはっきり変える**（BAN対策：つながりを隠すのではなく、内容を分ける）
- アカウント名（英小文字。シークレット名になる）、表示名、ユーザー名の候補、短い名前、既定のトピック、投稿時刻を決める
  - 投稿時刻は、そのジャンルの読者が見る時間に合わせる。ほかのアカウントと全部同じ時刻にしなくてよい

### 3. 一式を作る
```
python bot/new_account.py <アカウント名> --genre "<ジャンル>" --display-name "<表示名>" \
  --username <ユーザー名候補> --short-name <短い名前> --default-topic "<トピック>" \
  --slots 07:00 12:00 21:00 --tone "<口調を一言で>" --profile "<プロフィール文>
※PRを含みます"
```
作られたファイルの「（ここに書く）」をすべて埋める：
- `rules.md`：対象、ほかのアカウントとの違い、口調、1日の構成、トピック、書き方の注意、1行目の型（5〜8個）、**選手権・参加型のネタ帳（15個以上）**
- `reply_rules.md`：口調、このジャンルならではの返し方、慎重に扱う話題
- `商品候補.md`：10〜15個。商品のジャンル・例・合う投稿の場面・確認した出典。**リンクは作らない**（オーナーが作る）
- `立ち上げ手順.md`：プロフィール文が入っているか確認する。アイコンの案も一言書く

### 4. 最初の1週間分の案
- 開始予定日（オーナーの登録が終わる見込みの日。分からなければ1週間後の月曜）から7日分の `drafts/YYYY-MM-DD.json` を作る
- 商品リンクはまだ無いので、商品投稿は入れない（お役立ちで、後の商品投稿の伏線を張る）
- 週2回は選手権。1日目はあいさつを兼ねた参加型にする
- 各日について `python bot/check_drafts.py <日付> <アカウント名> --summary` を実行し、❌は必ず直す。⚠️（ほかのアカウントと似ている）も直す
- **承認用Issueは作らない**（停止中のため。稼働開始の前日に作る）

### 5. 保存と報告
- コミットして push する（`account.json` の追加で接続テストが自動で動き、「合鍵が未登録」と記録されるのは正常）
- オーナーへの報告（日本語、短く）：
  1. リサーチで分かった型と口調（3〜5行）と、ペットのアカウントとの違い
  2. 表示名・ユーザー名の候補・プロフィール文
  3. 最初の1週間の流れ（日ごとに1行）。全文は希望があれば見せる
  4. 商品候補の一覧（ジャンルと例だけ）
  5. `立ち上げ手順.md` の **1番だけ** を案内する（1つずつ進める取り決め）

## オーナーの登録が進んだら

- 「1番できた」：ユーザー名が候補と違えば `account.json` の `username` と `立ち上げ手順.md` を直して push。2番を案内する
- 「2番できた」：3番を案内する。**合鍵はチャットに貼らないよう、もう一度伝える**
- 「3番できた」：`accounts/<名前>/connection_request.txt` に今の日時を書いて push すると接続テストが動く。
  数分後に `git pull` して `accounts/<名前>/data/connection.txt` を読み、つながったアカウント名を報告する。違えば発行し直しを案内する
- 「4番できた」：5番（商品リンク）を案内する
- 1〜4が終わったら：`account.json` を `"enabled": true` にし、最初の数日は `"report": "full"`（全文を見せる）にして push。
  翌日分の案の承認用Issueを `ACCOUNT=<名前> python bot/create_draft_issue.py accounts/<名前>/drafts/<日付>.json` で作り、全文を見せる
- 合鍵の自動更新（「合鍵を自動更新」）は、全アカウントを毎週まとめて延長する。新しいアカウントの追加作業は要らない
