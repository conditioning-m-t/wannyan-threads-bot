# 新しいアカウントの共通ルール（accounts/ 以下）

ジャンルごとのThreadsアカウントを、1つの仕組みで運用する。目的は**アフィリエイトでの収益化**。オーナーは日本人（田代さん）。
ペットのアカウント（@wannyan_pick）は手本で、運用は別のチャットが担当する（ペットのファイル・自動実行・説明書には触らない）。
**説明・報告・途中経過はすべて日本語で書く。英語は通じないので使わない。**

## アカウントの一覧と置き場所

アカウントごとのものは `accounts/<アカウント名>/` にまとめる。

| ファイル | 中身 |
|---|---|
| `account.json` | Threadsのユーザー名・表示名・稼働中か（`enabled`）・投稿時刻・既定のトピック・報告の仕方（`report`） |
| `rules.md` | そのアカウントの運用ルール（対象・1日の構成・口調・型・ネタ帳・週次レポート）。**案を作る前に必ず読む** |
| `reply_rules.md` | コメント返信のルール（自動返信のAIにそのまま渡す） |
| `products.json` | オーナーが作ったAmazonリンクと、出典つきの事実・注意点 |
| `drafts/YYYY-MM-DD.json` | 投稿案 |
| `data/` | 反応データ・フォロワー数・返信の記録・保留コメント・接続テストの結果 |

| アカウント名 | Threads | ジャンル | 状態 |
|---|---|---|---|
| `kaji` | 「家事サボり姉さん」（ユーザー名は変更予定） | 家事・掃除・収納の時短（姉さん口調） | 停止中（オーナーの登録待ち） |

コマンドには必ず先頭に `ACCOUNT=<アカウント名>` を付ける（省くとペットのアカウントになってしまう）。

## オーナーとの取り決め（必ず守る）

- **合鍵（トークン）をチャットに貼らせない・スクショさせない。** ファイル・ログ・コミットにも書かない。シークレットには触れない
- オーナーはGitHubアプリを使わない。GitHubの操作はこちらで行う。
  例外：シークレット登録など、こちらから変更できないものだけ、手順を1つずつ日本語で案内する
- **運用中のアカウントを止めない・壊さない。** 変更は投稿しない試し実行（`DRY_RUN=1`）・返信の下見（`REPLY_TEST=preview`）・手元のテストで確認してから入れる
- 別のチャット（ペット運用）も同じリポジトリに push する。**push の前は毎回 `git pull --rebase origin main`** し、ほかのチャットの変更を消さない
- アカウント作成・パスワード入力・Metaアプリの公開や審査申請は、オーナー本人が行う
- **BAN対策は正攻法のみ。** アカウントごとにジャンル・口調・内容をはっきり分け、似た投稿を量産しない。IPや端末の偽装など、アカウント同士のつながりを隠す仕組みは作らない
- 「いいね」の自動化と、他人の投稿への自動コメントはしない（規約違反・スパム扱いの危険）
- **Threadsへ直接投稿しない。** 投稿は GitHub Actions が行う

## 毎晩の下書き作成の手順（稼働中のアカウントごとに行う）

1. `git pull` で最新にする
2. `accounts/<名前>/rules.md` を読む
3. `accounts/<名前>/data/insights.json` で直近の反応（views / likes / replies）を確認し、伸びた型・伸びなかった型を把握する
4. `accounts/<名前>/drafts/` の過去の案を見て、同じ切り口が続かないようにする
5. 翌日の季節・天気・行事・そのジャンルの話題をWeb検索で軽く調べる
6. 翌日分の `accounts/<名前>/drafts/YYYY-MM-DD.json` を作る（形式は下記）
7. `python bot/check_drafts.py YYYY-MM-DD <名前> --summary` で自動チェックする。❌は必ず直す。⚠️（似すぎ・絵文字の数など）も原則直す
8. `ACCOUNT=<名前> python bot/create_draft_issue.py accounts/<名前>/drafts/YYYY-MM-DD.json` で承認用Issueを作る。問題が出たら案を直して再実行する
9. 下書きファイルをコミットして push する
10. 報告する（`account.json` の `report` による）
   - `full`：3案の本文を時刻ごとに全文で表示する（下記「止めたい時だけ言う方式」）
   - `summary`：`check_drafts.py --summary` の結果をもとに、アカウントごとに時刻・種類・狙いを1行ずつ。自動チェックで⚠️が残った案だけ全文で見せる
11. `accounts/<名前>/data/escalations.json` に未報告のコメントがあれば要約して報告する（下記「コメントへの自動返信」）
12. `accounts/<名前>/data/token_status.json` を見て、合鍵の更新に失敗している（`ok: false`）か、期限（`expires_at`）や
    書き換え用の合鍵の期限（`writer_expires`）が14日以内なら、オーナーに知らせる

週次レポートや関門の判定など、アカウントごとの追加作業は `rules.md` に書いてある。

## 止めたい時だけ言う方式

案は**承認済みの状態で作られ、何も言われなければその時刻に自動投稿される**。
オーナーはこのClaudeとのやり取りだけで止める・直す。GitHubの操作をお願いしない。

- 案を見せたら最後に「このまま自動で投稿します。止めたい・直したい案があれば教えてください（例：2番やめて／3番の◯◯を変えて）」と添える。アカウントが複数あるときは、どのアカウントの何番かが分かるように番号を振る
- 返信を受けたら次のコマンドで反映し、結果を短く報告する（先頭に必ず `ACCOUNT=<名前>`）
  - 止める：`ACCOUNT=<名前> python bot/approve.py YYYY-MM-DD --unapprove 12:00`
  - 止めた案を戻す：`ACCOUNT=<名前> python bot/approve.py YYYY-MM-DD --approve 12:00`
  - 本文の修正：`accounts/<名前>/drafts/YYYY-MM-DD.json` を直してから
    `ACCOUNT=<名前> python bot/approve.py YYYY-MM-DD --sync accounts/<名前>/drafts/YYYY-MM-DD.json`（修正後の下書きはコミットしてpush）
  - 状態確認：`ACCOUNT=<名前> python bot/approve.py YYYY-MM-DD --show`
- 修正したら、直した本文を全文で見せる（「この内容で投稿します」）

## コメントへの自動返信

Actions「新アカウント：投稿とコメント返信」がアカウントごとに**2分おきに**新しいコメントを確認し、あればすぐAI（Claude）で返信する（オーナーの希望で10分以内が目標）。
ルールは `accounts/<名前>/reply_rules.md`。こちらの返信への返信にも、1人3往復まで返す（ほかの人どうしの会話には入らない）。
すでにこちらが返信しているコメントには、記録が無くても二度返信しない。
リポジトリは公開（Actionsを無料で回すため）。トークンなど秘密の値はファイルやログに絶対に書かない。
判断が必要なコメント（苦情・トラブル・商品の質問・個人的な相談・不適切な内容）は返信せず `accounts/<名前>/data/escalations.json` に記録される。
毎晩の作業で未報告のもの（`reported: false`）があれば、内容を要約してオーナーに報告し、`reported: true` にしてコミットする。
報告するときは返信文の案も添える。オーナーが「返して」「この文で」と言ったら、`accounts/<名前>/data/manual_replies.json` に
`[{"comment_id": "...", "username": "...", "text": "返信文"}]` の形で追加してコミット・pushする（2分以内に自動で投稿される）。

## 商品リンクの登録

オーナーがチャットにAmazonアソシエイトのリンク（link.amazon/… など）と商品名を貼ったら：

1. どのアカウントの商品か確かめる（分からなければオーナーに聞く）
2. 商品ページの内容や第三者の検証記事をWeb検索で確認し、出典つきの事実だけを `facts` に、弱点や注意点を `cautions` に書く
3. `accounts/<名前>/products.json` に追加してコミット・push する
4. 登録した内容（商品名・リンク・使える事実）を短く報告する

リンクが商品名と一致しているか確認できない場合は、オーナーに確認する。

## 書き方のルール（全アカウント共通・必須）

- **AIで作ったことの表示**：Amazonアソシエイトの2026年4月20日の規約改定で、AIを使って作ったコンテンツに「AIにより作成」等の表示が求められているとの解説がある（公式原文はオーナーが確認中）。
  確認が取れるまでは、プロフィールに「※PRを含みます／投稿はAIで作成しています」を入れておく
- 1投稿は500文字以内。目安は80〜200文字。絵文字は2個まで
- 各案に `topic` を1つ付ける（50文字以内、「.」「&」不可）。付け忘れると `account.json` の `default_topic` になる
- **1投稿目にURLを入れない。** 商品リンクはツリー2投稿目（`reply`）に置く
- **商品リンクの直後に半角スペースと `PR` を付ける**（例：`https://link.amazon/xxxx PR`）。1投稿目には付けない。「アフィリエイトです」などの長い説明は不要。プロフィールには「※PRを含みます」を入れる
- PRをハッシュタグの中に混ぜない（埋もれると表示として不十分になるため）
- 商品はそのアカウントの `products.json` にあるものだけを使う。リンクもそこにあるものだけ（自分でリンクを作らない）
- 商品の良さは `facts` に書かれた事実の範囲で書く。「1位」「売れてる」「選ばれている」など根拠のない表現は使わない
- 悩みを「少し」「ちょっと」で弱めない。当事者が自分ごとだと思える具体的な場面を書く
- 「〜な方に」「・箇条書き3つ」「選ばれています」の広告文の型は使わない。毎回、型を変える
- 煽りすぎない（攻撃的・ネガティブすぎる表現は表示を落とされる）
- 健康・お金・美容などで効果を断定しない。一般論にとどめる
- 締めは返信しやすい問いかけにする（一言で答えられる、選択肢がある）
- 「フォローして」「いいねして」の連呼はしない
- 人気アカウントの**型・口調・リズムは参考にするが、文章そのものは絶対に写さない**（著作権の問題になり、似た文章の量産はThreadsで低品質と判断される）
- **ほかのアカウントの案と、切り口・1行目・言い回しを似せない**（アカウントごとに口調をはっきり分ける）

## drafts/YYYY-MM-DD.json の形式

```json
{
  "date": "2026-10-20",
  "posts": [
    {
      "slot": "07:00",
      "type": "参加型",
      "memo": "この案の狙いを一言（承認する人が判断しやすいように）",
      "text": "1投稿目の本文",
      "reply": null,
      "topic": "家事のコツ"
    },
    {
      "slot": "12:00",
      "type": "商品",
      "memo": "...",
      "text": "1投稿目の本文",
      "reply": "これ👇\nhttps://link.amazon/xxxx PR",
      "topic": "家事のコツ"
    }
  ]
}
```

`slot` は `account.json` の `slots` のどれか。

## 新しいアカウントの立ち上げ

オーナーが「〇〇ジャンルで立ち上げて」と言ったら、スキル `launch-account`（`.claude/skills/launch-account/SKILL.md`）の手順で進める。
一式は `python bot/new_account.py` で停止中のまま作り、オーナーの登録（アカウント作成・テスター追加・合鍵の登録・Amazonの登録サイト追加）が
終わって接続テストに合格してから稼働中にする。

## 仕組みの構成

- ペットと同じコード（`bot/`）を、環境変数 `ACCOUNT` でアカウントを切り替えて使う。設定とファイルの置き場所は `bot/account.py`
- Actions「新アカウント：投稿とコメント返信」（`accounts-bot.yml`）：`enabled: true` のアカウントごとに並列で、約27分間、2分おきに投稿と返信をくり返す（`bot/loop.sh`）
- Actions「新アカウント：反応データを収集」（17:47）：`accounts/<名前>/data/insights.json`・`followers.json`
- Actions「新アカウント：接続テスト」：`account.json` か `connection_request.txt` を更新して push すると動き、結果が `accounts/<名前>/data/connection.txt` に残る（Actionsのログは読めないため）
- Actions「合鍵を自動更新」（毎週月曜4:17）：書き換え用の合鍵（`SECRETS_WRITER_TOKEN`）が登録されていれば、合鍵を延長してシークレットに書き戻す。結果は `accounts/<名前>/data/token_status.json`
- `bot/check_drafts.py`：投稿案の自動チェック（形式・商品リンク・過去の案やほかのアカウントとの似すぎ）
- `bot/new_account.py` ＋ `templates/account/`：新しいアカウントの一式を作る
- 合鍵のシークレット名は `THREADS_ACCESS_TOKEN_<アカウント名を大文字>`（例：`THREADS_ACCESS_TOKEN_KAJI`）
- ジャンル選定の根拠：`research/2026-10_ジャンル選定.md`
